# CI/CD do site da SNCT — plano de implementação

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Tirar a construção da imagem da VPS e permitir deployar e voltar atrás pelo grupo do Telegram, sem abrir terminal.

**Architecture:** O GitHub Actions roda os 134 testes e, no push para `main`, publica a imagem no GHCR com duas tags (`sha-<short>` imutável e `latest`). A VPS deixa de construir: o `docker-compose.override.yml` aponta para a imagem do GHCR e a tag corrente vive numa variável do `.env`. Três scripts em `~/telegram-ops/bin/` (`deploy`, `rollback`, `versoes`) fazem o trabalho, e o agente do Telegram apenas os invoca — ele nunca executa comando.

**Tech Stack:** GitHub Actions, GHCR, Docker Compose v5, Django 5.2, PostgreSQL 17, bash, Python 3 (daemon do bot).

**Spec:** `docs/superpowers/specs/2026-09-29-cicd-snct-design.md`

## Global Constraints

- Imagem: `ghcr.io/polarif/snct2026` — **minúsculo**, o GHCR rejeita maiúsculas.
- Duas tags por publicação: `sha-<short>` (7 caracteres, imutável) e `latest`.
- A imagem carrega `org.opencontainers.image.revision=<sha completo>`.
- Pacote **público**: a VPS puxa sem autenticação, sem token guardado lá.
- Testes do CI rodam contra **PostgreSQL 17**, espelhando produção — não SQLite.
- `collectstatic` roda **antes** dos testes; sem o manifest a suíte inteira quebra.
- Os scripts **nunca** passam `--build` ao compose.
- O agente do Telegram **só invoca scripts de `bin/`**; nunca comandos soltos.
- `DEPLOY_PERMITIDO` é decidido pelo daemon, fora do modelo.
- `deploy`/`rollback` sem `--sim` são dry-run.
- Limite de um deploy a cada 120 segundos.
- Espera pelo healthcheck: **120s** (o `HEALTHCHECK` tem `start-period=40s` e
  `interval=30s`, logo o container fica `healthy` entre 40s e ~100s; o spec
  dizia 90s, que não cobre uma primeira sondagem falha).
- Caminho da VPS: `~/snct2026` (projeto) e `~/telegram-ops` (bot). Acesso: `ssh vps-anesp`.
- Mensagens de commit e comentários em português do Brasil, como o resto do projeto.

## Review Focus

Classes de entrada que o spec implica e que precisam de teste próprio:

1. **Tag inexistente no GHCR** (`deploy sha-naoexiste`) — deve recusar antes de tocar no `.env` ou no container; o site não pode ficar meio-atualizado. *(Task 5)*
2. **Rollback sem histórico** — primeiro uso, arquivo ausente ou com uma linha só: deve explicar, não quebrar com erro de bash. *(Task 6)*
3. **Container que nunca fica `healthy`** — o rollback automático precisa funcionar de verdade, não só existir no código. *(Task 5)*
4. **Deploy pedido por quem não pode** (`DEPLOY_PERMITIDO=0`) — recusa determinística, independente do que o agente concluiu. *(Task 7)*
5. **Dois deploys ao mesmo tempo** — o segundo tem que esperar ou recusar; dois `up -d` concorrentes no mesmo serviço deixam estado imprevisível. *(Task 5)*

### Task 2: Publicar a imagem no GHCR

**Files:**
- Modify: `.github/workflows/ci.yml` (acrescenta o job `publica`)

**Interfaces:**
- Consumes: job `testes` da Task 1, via `needs: testes`.
- Produces: imagem `ghcr.io/polarif/snct2026` com as tags `sha-<short>` e `latest`, e o label `org.opencontainers.image.revision`.

- [ ] **Step 1: Acrescentar o job de publicação ao fim do ci.yml**

```yaml
  publica:
    # Só em push na main: um PR não publica imagem.
    if: github.event_name == 'push'
    needs: testes
    runs-on: ubuntu-latest

    # packages:write é o que autoriza publicar no GHCR. A autenticação usa o
    # GITHUB_TOKEN da própria execução — não há segredo a criar nem rotacionar.
    permissions:
      contents: read
      packages: write

    steps:
      - uses: actions/checkout@v4

      - name: Encurtar o SHA
        id: sha
        run: echo "curto=$(echo ${{ github.sha }} | cut -c1-7)" >> "$GITHUB_OUTPUT"

      - uses: docker/setup-buildx-action@v3

      - uses: docker/login-action@v3
        with:
          registry: ghcr.io
          username: ${{ github.actor }}
          password: ${{ secrets.GITHUB_TOKEN }}

      - name: Construir e publicar
        uses: docker/build-push-action@v6
        with:
          context: .
          push: true
          tags: |
            ghcr.io/polarif/snct2026:sha-${{ steps.sha.outputs.curto }}
            ghcr.io/polarif/snct2026:latest
          # O label é o que deixa um deploy de "latest" registrar QUAL commit
          # subiu. Sem ele, "latest" no histórico não significa nada depois do
          # próximo merge.
          labels: |
            org.opencontainers.image.revision=${{ github.sha }}
          cache-from: type=gha
          cache-to: type=gha,mode=max
```

### Task 4: Funções comuns e o script `versoes`

**Files:**
- Create (VPS): `~/telegram-ops/bin/_deploy_comum.sh`
- Create (VPS): `~/telegram-ops/bin/versoes`

**Interfaces:**
- Consumes: `SNCT_TAG` no `.env` (Task 3).
- Produces, para as Tasks 5 e 6:
  - `tag_atual() -> string` — lê `SNCT_TAG` do `.env`
  - `escreve_tag(tag)` — grava `SNCT_TAG` no `.env`
  - `existe_no_ghcr(tag) -> 0|1` — a tag existe no registro
  - `revision_da_imagem(tag) -> sha40|""` — lê o label `org.opencontainers.image.revision`
  - `espera_saudavel(segundos) -> 0|1` — aguarda o container ficar `healthy`
  - `registra(tag, sha, quem, resultado)` — acrescenta linha ao histórico
  - `tag_anterior() -> string|""` — penúltima tag com resultado `ok`
  - `trava()` — `flock` que impede dois deploys simultâneos
  - `respeita_intervalo() -> 0|1` — recusa se o último deploy foi há menos de 120s

- [ ] **Step 1: Escrever as funções comuns**

```bash
cat > ~/telegram-ops/bin/_deploy_comum.sh <<'EOF'
#!/usr/bin/env bash
# Funcoes compartilhadas por deploy, rollback e versoes.
# Nao e executavel sozinho: os outros scripts fazem "source" deste arquivo.

PROJETO=/home/eduardo/snct2026
IMAGEM=ghcr.io/polarif/snct2026
HISTORICO="$PROJETO/.deploy-historico"
ESPERA_SAUDE=120        # HEALTHCHECK tem start-period 40s + interval 30s
TRAVA=/tmp/snct-deploy.lock
INTERVALO_MIN=120       # segundos entre dois deploys

tag_atual() {
    grep -E '^SNCT_TAG=' "$PROJETO/.env" 2>/dev/null | cut -d= -f2- | tr -d ' '
}

escreve_tag() {
    local nova="$1"
    if grep -qE '^SNCT_TAG=' "$PROJETO/.env"; then
        sed -i "s|^SNCT_TAG=.*|SNCT_TAG=$nova|" "$PROJETO/.env"
    else
        printf '\nSNCT_TAG=%s\n' "$nova" >> "$PROJETO/.env"
    fi
}

existe_no_ghcr() {
    docker manifest inspect "$IMAGEM:$1" >/dev/null 2>&1
}

revision_da_imagem() {
    docker image inspect "$IMAGEM:$1" \
        --format '{{index .Config.Labels "org.opencontainers.image.revision"}}' 2>/dev/null
}

espera_saudavel() {
    local limite="${1:-$ESPERA_SAUDE}" passou=0
    while [ "$passou" -lt "$limite" ]; do
        case "$(docker inspect -f '{{.State.Health.Status}}' snct2026-web-1 2>/dev/null)" in
            healthy)   return 0 ;;
            unhealthy) return 1 ;;
        esac
        sleep 5; passou=$(( passou + 5 ))
    done
    return 1
}

registra() {   # tag  sha  quem  resultado
    printf '%s\t%s\t%s\t%s\t%s\n' \
        "$(date -u +%Y-%m-%dT%H:%M:%SZ)" "$1" "${2:-?}" "${3:-?}" "$4" >> "$HISTORICO"
}

# Penultima tag que deu certo. A ultima linha ok e o que esta rodando agora,
# entao voltar atras significa a anterior a ela.
tag_anterior() {
    [ -f "$HISTORICO" ] || return 0
    awk -F'\t' '$5=="ok"{print $2}' "$HISTORICO" | tail -2 | head -1
}

# Trava contra repetir deploy sem querer (mensagem duplicada, agente insistindo).
# NAO vale para rollback: voltar atras e justamente o que se quer fazer rapido
# quando algo deu errado, e fazer esperar dois minutos seria o oposto.
respeita_intervalo() {
    [ -f "$HISTORICO" ] || return 0
    local ultimo t_ultimo falta
    ultimo=$(tail -1 "$HISTORICO" | cut -f1)
    [ -n "$ultimo" ] || return 0
    t_ultimo=$(date -u -d "$ultimo" +%s 2>/dev/null) || return 0
    falta=$(( INTERVALO_MIN - ( $(date -u +%s) - t_ultimo ) ))
    if [ "$falta" -gt 0 ]; then
        echo "o ultimo deploy foi ha pouco; espere ${falta}s (ou use rollback, que nao espera)"
        return 1
    fi
    return 0
}

# Dois "up -d" concorrentes no mesmo servico deixam estado imprevisivel.
trava() {
    exec 9>"$TRAVA"
    flock -n 9 || { echo "ja ha um deploy em andamento; tente em instantes"; exit 1; }
}
EOF
chmod +x ~/telegram-ops/bin/_deploy_comum.sh
```

# O que existe para deployar, o que roda agora e o que ja foi deployado.
#   versoes        -> ultimas 10 imagens

TOKEN=$(cat /tmp/.ghcr_token 2>/dev/null); rm -f /tmp/.ghcr_token

### Task 5: O script `deploy`

**Files:**
- Create (VPS): `~/telegram-ops/bin/deploy`

**Interfaces:**
- Consumes: todas as funções de `_deploy_comum.sh` (Task 4); `DEPLOY_PERMITIDO` do ambiente (Task 7).
- Produces: linhas no `.deploy-historico` que o `rollback` (Task 6) lê.

- [ ] **Step 1: Escrever o script**

```bash
cat > ~/telegram-ops/bin/deploy <<'EOF'
#!/usr/bin/env bash
# Atualiza a producao do site da SNCT com uma imagem ja construida pelo CI.
#
#   deploy              -> dry-run: mostra o que faria com a latest
#   deploy --sim        -> aplica a latest
#   deploy sha-abc1234  -> dry-run daquela versao
#   deploy sha-abc1234 --sim
#
# Sem --sim nada e alterado. E de proposito: quem chama este script e o agente
# do Telegram, e um pedido ambiguo nao pode virar deploy.
set -euo pipefail
. "$(dirname "$0")/_deploy_comum.sh"

# Quem pode deployar e decidido pelo daemon, fora do modelo. Se o agente
# concluiu que devia deployar mas quem pediu nao tem permissao, para aqui.
if [ "${DEPLOY_PERMITIDO:-0}" != "1" ]; then
    echo "Esta pessoa nao tem permissao para deployar."
    echo "A lista fica em DEPLOY_USER_IDS, no config.env do bot."
    exit 1
fi

ALVO=latest; APLICAR=0
for arg in "$@"; do
    case "$arg" in
        --sim) APLICAR=1 ;;
        -*)    echo "argumento desconhecido: $arg"; exit 1 ;;
        *)     ALVO="$arg" ;;
    esac
done

ATUAL=$(tag_atual)
echo "atual : ${ATUAL:-(nenhuma)}"
echo "alvo  : $ALVO"

if ! existe_no_ghcr "$ALVO"; then
    echo
    echo "A tag '$ALVO' nao existe no GHCR. Nada foi alterado."
    echo "Use 'versoes' para ver o que esta disponivel."
    exit 1
fi

if [ "$ALVO" = "$ATUAL" ]; then
    echo; echo "Ja e a versao que esta rodando. Nada a fazer."
    exit 0
fi

# Puxa antes de decidir: e assim que da para ler o label e avisar de migracao
# ainda no dry-run.
docker pull -q "$IMAGEM:$ALVO" >/dev/null
SHA_ALVO=$(revision_da_imagem "$ALVO")
SHA_ATUAL=$(revision_da_imagem "${ATUAL:-$ALVO}")
echo "commit: ${SHA_ALVO:0:7}"

MIGRACOES=""
if [ -n "$SHA_ATUAL" ] && [ -n "$SHA_ALVO" ] && [ "$SHA_ATUAL" != "$SHA_ALVO" ]; then
    MIGRACOES=$(git -C "$PROJETO" diff --name-only "$SHA_ATUAL" "$SHA_ALVO" 2>/dev/null \
                | grep 'migrations/' | grep -v '__init__' || true)
fi
if [ -n "$MIGRACOES" ]; then
    echo
    echo "ATENCAO: esta versao traz migracao de banco:"
    echo "$MIGRACOES" | sed 's/^/  /'
    echo "Rollback NAO desfaz migracao. Voltar depois pode nao funcionar."
fi

if [ "$APLICAR" != "1" ]; then
    echo
    echo "(simulacao -- nada foi alterado. Para aplicar, repita com --sim)"
    exit 0
fi

trava                                    # dois ao mesmo tempo: nao
[ "${PULA_INTERVALO:-0}" = "1" ] || respeita_intervalo || exit 1

echo
echo "aplicando..."
escreve_tag "$ALVO"
cd "$PROJETO"
docker compose up -d web          # sem --build, de proposito

if espera_saudavel; then
    registra "$ALVO" "$SHA_ALVO" "${OPS_QUEM:-?}" ok
    echo "deploy ok: $ALVO (${SHA_ALVO:0:7})"
    exit 0
fi

echo "o container nao ficou saudavel; voltando para ${ATUAL:-a anterior}"
registra "$ALVO" "$SHA_ALVO" "${OPS_QUEM:-?}" falhou
if [ -n "$ATUAL" ]; then
    escreve_tag "$ATUAL"
    docker compose up -d web
    espera_saudavel && echo "voltou para $ATUAL" || echo "ATENCAO: nem a anterior subiu; olhe a VPS"
fi
exit 1
EOF
chmod +x ~/telegram-ops/bin/deploy
```

### Task 6: O script `rollback`

**Files:**

- [ ] **Step 1: Escrever o script**

```bash
cat > ~/telegram-ops/bin/rollback <<'EOF'
#!/usr/bin/env bash
# Volta a producao para a versao anterior.
#
#   rollback             -> dry-run da versao anterior do historico
#   rollback --sim       -> aplica
#   rollback sha-abc1234 -> volta para uma versao especifica
#
# E o mesmo caminho do deploy, de proposito: um codigo so, um caminho testado.
set -euo pipefail
. "$(dirname "$0")/_deploy_comum.sh"

ALVO=""; APLICAR=""
for arg in "$@"; do
    case "$arg" in
        --sim) APLICAR="--sim" ;;
        -*)    echo "argumento desconhecido: $arg"; exit 1 ;;
        *)     ALVO="$arg" ;;
    esac
done

if [ -z "$ALVO" ]; then
    ALVO=$(tag_anterior)
    if [ -z "$ALVO" ]; then
        echo "Nao ha versao anterior registrada no historico."
        echo "Use 'versoes' para ver o que existe no GHCR e passe a tag:"
        echo "  rollback sha-abc1234 --sim"
        exit 1
    fi
    echo "versao anterior no historico: $ALVO"
fi

# Rollback nao espera o intervalo: e operacao de emergencia.
PULA_INTERVALO=1 exec "$(dirname "$0")/deploy" "$ALVO" $APLICAR
EOF
chmod +x ~/telegram-ops/bin/rollback
```
